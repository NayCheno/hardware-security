\begin{frame}[t]{全局总结与研究启示}
\DeckKicker{全局总结}
\ClaimLine{可信执行边界正在从 CPU 内部隔离扩展到内存、I/O fabric 与异构设备数据路径。}
\begin{columns}[T,totalwidth=\textwidth]
  \begin{column}{0.48\textwidth}
    \TextPanel{技术结论}{\begin{itemize}
      \item 早期 TEE 主要解决 CPU 与内存隔离；新一代机密计算必须纳入设备、DMA、interrupt 和远端 verifier。
      \item Arm CCA 与 RISC-V CoVE/AP-TEE 代表架构级 confidential VM 路线，但可信 I/O 仍处在规范与系统原型共同演进阶段。
      \item CXL、SPDM/TDISP、DPU、GPU 与 SmartNIC 使保护边界从本地内存走向跨 fabric 数据路径。
    \end{itemize}}
  \end{column}
  \begin{column}{0.46\textwidth}
    \VisualPanel{研究空白}{\begin{itemize}
      \item 统一的 device identity、lifecycle 与 attestation 语义仍不成熟。
      \item 可信 I/O 的性能、安全和可部署性需要更多公开系统评测。
      \item 异构设备与存储路径中的 TCB 划分、策略编排和故障恢复仍缺少通用框架。
      \item 未来工作应同时关注规范互操作、真实工作负载和端到端证据链。
    \end{itemize}}
  \end{column}
\end{columns}
\end{frame}
