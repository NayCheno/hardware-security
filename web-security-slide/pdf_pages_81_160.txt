核心模块3：基于聚类分析的未保护接口识别
➢ 设计目标：应对非标准 HTTP 响应的无监督聚类
➢ 针对 IoT Web 服务器不规范的错误处理机制（如用 200 OK 伪装 404 Not 
Found），IoTScope 引入了轻量级响应聚类算法：
1. 响应相似度度量 (Similarity Measurement)：不依赖 HTTP 状态码，而是计算两个
响应报文内容的字符串相似度：Similarity(a,b)=2∗Mab/(La+Lb)
2. 无监督分组 (Clustering)：将收集到的所有匿名响应报文进行相似度聚类
3. 多数派过滤 (Majority Filtering)：
• 绝大数盲测 URL 都是不存在的无效路径，服务器会返回格式一致的默认错误页面
• 因此，聚类后规模最大的几个组（Majority）代表了无效接口，将其剔除；而那些游
离的少数派（Minority / Outliers）则被确认为真实存在且无访问控制的未保护接口

核心模块1：基于响应的执行轨迹推断
➢ 设计目标：从响应文本逆推深层代码覆盖率
➢ 在无法插桩的情况下，LABRADOR 创新性地将字符串作为追踪锚点：
1. 显式字符串与显式块 (Explicit Strings & Blocks)：静态提取后端二进制中能够输出到响应的字符串

含关系匹配
3. 轨迹重构：若响应中的文本与二进制中的潜在显式字符串相似度超过阈值，则认定该字符串对应的

核心模块3：节点优先级与定向变异（下）
➢ 设计目标：精准分析高价值语义节点的变异引擎
➢ 在分配能量后，LABRADOR 需决定对树模型中的哪些节点实施何种变异：
1. 节点选择概率 (Mutation Probability)：节点的选中概率由四个维度联合决定：
• 节点增益 (Gain)：到达 Sink 的理论概率越高，优先级越高
• 树深度 (Depth)：越深层的节点通常代表后端更复杂的解析路径，优先级越高
• 所在区域 (Domain)：不同区域赋予不同基础权重（如 Parameter 区域权重极高）
• 动态距离修正：结合最新响应反馈，向上调优那些使得执行轨迹更接近 Sink 的节点概率
2. 双层变异算子 (Mutation Operators)
• 类型算子：感知目标 Sink 类型（如命令注入需插入 ; 或 |）与数据类型（如数字极值替换）
• 结构算子：对树的子节点进行复制、添加、删除或替换，实现大规模路径探索

研究背景：静态与动态分析及 PoC 生成的困境
1. 静态分析的误报与验证负担
• 现有静态工具（如 SaTC）能够发现潜在的漏洞位置，但缺乏自动验证其真实性的能力
• 这要求安全分析师投入大量人工成本进行漏洞分流与确认
2. 动态模糊测试的可达性盲区
• 由于物联网固件中大量条件分支与特定输入值紧密绑定，模糊测试往往无法覆盖大部分代码库
• 经验证，模糊测试平均只能到达约 25% 的汇聚点（Sink），这意味着仅依赖 Fuzzing 会遗漏大量深
层漏洞
• 研究目标：自动合成有效 PoC 的闭环验证方案
• 结合 Fuzzing 收集的真实可达输入源（消除误报源头）
• 利用大模型进行复杂上下文数据流追踪（消除漏报）
